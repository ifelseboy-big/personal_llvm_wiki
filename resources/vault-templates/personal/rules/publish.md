# 可信知识发布规则

Agent 根据 `AGENTS.md`、本文件、质量规则和选用模板判断知识语义；CLI 不解析自然语言治理规则，只保证来源、哈希、事务、路径和写入完整性。

1. 只有 `llm-wiki publish apply` 可以提交 `knowledge/`。
2. 发布草稿至少包含标题、知识类型、清晰正文和一个有效 raw 来源。
3. 发布前检查来源哈希；来源或目标知识发生变化时，原提案必须失效并重新审阅。
4. 事实陈述与推断必须分开。无法由来源支持的结论标为“推断”或“待验证”。
5. 更新已有主题时优先修改现有 knowledge ID，不创建同义副本。
6. 冲突来源不能被静默合并；正文应说明分歧、时间和各自证据。
7. `publish diff` 是审阅材料，`publish apply` 是明确审批点。

`publish apply` 成功后，`knowledge/` 中的发布 Markdown 立即成为唯一最终事实。后续派生构建或索引更新失败只能产生运行警告，不能让 SQLite 或 `llm-wiki/` 取代该文件。
