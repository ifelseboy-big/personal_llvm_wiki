# 生命周期与时间有效性

`lifecycle` 描述知识内容是否仍可作为事实使用，和系统发布状态、决策执行状态、项目推进状态相互独立。

| 值 | 含义 | 默认检索行为 |
| --- | --- | --- |
| `current` | 目前可用，未发现足以否定它的证据 | 正常返回 |
| `disputed` | 存在重要冲突或证据不足 | 返回并显示警告 |
| `superseded` | 已被更新知识替代 | 默认排除，允许显式查询 |
| `retracted` | 已确认不应继续作为事实使用 | 默认排除，允许审计查询 |

## 时间字段

- `valid_from`：事实开始适用的日期或时间。
- `valid_until`：事实停止适用的日期或时间。
- `review_after`：到期后需要人工复核，不等于事实自动失效。
- `updated_at`：系统记录的文件更新时间，不能替代事实有效期。

时间未知时省略属性，不要写“未知”、空字符串或猜测值。

## 转换规则

- 新知识默认 `current`。
- 出现尚未解决的可靠反证时转为 `disputed`，并在正文记录冲突来源。
- 新知识完整替代旧知识时，旧知识转为 `superseded`；旧文档的 `superseded_by` 与新文档的 `supersedes` 必须成对指向真实知识文件。
- 确认内容错误、伪造或不再允许使用时转为 `retracted`，正文保留原因和证据。
- 不删除历史知识来表达失效。生命周期转换必须保留可审计轨迹。

`decision_state` 只描述决策是否提出、接受或废弃；`project_state` 只描述项目是否活跃、暂停或结束。它们不能代替 `lifecycle`。

## 查询与检查

- 普通查询优先 `current`，对 `disputed` 显示显著警告。
- `valid_until` 已过去但仍为 `current` 的文档进入复核视图。
- `review_after` 到期不会自动改状态，但 `llm-wiki doctor` 应报告。
- 失效知识仍可被引用，但引用处必须明确它是历史依据，不能伪装成当前事实。
