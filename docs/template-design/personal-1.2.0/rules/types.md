# 知识类型

每篇已发布知识只选择一个主类型。类型描述文档的主要用途，不描述文件所在目录。

| 类型 | 用途 | 核心问题 | 不应包含 |
| --- | --- | --- | --- |
| `claim` | 保存可核验的原子结论 | 什么是真的，在什么条件下成立？ | 完整教程、操作手册 |
| `concept` | 解释概念、机制与边界 | 它是什么，为什么如此？ | 仅有一句结论的摘录 |
| `guide` | 帮助读者完成现实任务 | 如何可靠地完成一件事？ | 以教学进程为主的课程 |
| `tutorial` | 通过连续练习达成学习成果 | 如何一步步学会？ | 纯参数清单 |
| `reference` | 提供可快速查找的规范事实 | 精确字段、接口、约束是什么？ | 依赖叙事才能理解的教程 |
| `decision` | 记录选择、理由与后果 | 为什么在这些选项中这样选？ | 没有取舍的会议记录 |
| `project` | 保存某一时点的项目事实快照 | 当前目标、范围、状态和风险是什么？ | 动态任务队列、个人待办 |

## 选择方法

1. 能写成一个可证伪的完整句子，选择 `claim`。
2. 主要解释定义、机制或边界，选择 `concept`。
3. 读者要完成任务，选择 `guide`；读者要获得能力，选择 `tutorial`。
4. 读者会按字段、命令或约束查找，选择 `reference`。
5. 核心事实是一次选择及其理由，选择 `decision`。
6. 核心事实是项目在某一时点的状态，选择 `project`。

一篇文档同时承担多个主要用途时应拆分，并通过 `related` 连接。不要用 `project` 替代任务管理，也不要把所有项目资料聚合到一篇持续膨胀的文档。

## 标题规则

- `claim` 使用完整结论，例如“SQLite 索引可以重建，知识文件不能由索引反写”。
- `concept` 使用稳定名词，例如“发布提案”。
- `guide` 使用任务目标，例如“恢复损坏的搜索索引”。
- `tutorial` 使用学习成果，例如“从零建立第一个本地知识库”。
- `reference` 使用被查对象，例如“知识文档属性参考”。
- `decision` 使用已选择或待选择的问题，例如“采用 Markdown 作为事实载体”。
- `project` 使用项目名加快照语义，例如“llm-wiki 项目状态”。
