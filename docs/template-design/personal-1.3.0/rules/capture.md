# 原始资料采集规则

Agent 在每个知识库工作流的第一次 `raw add` 前必须读取本文件和 [[rules/metadata|元数据规则]]。同一任务、同一 wiki 且规则未变化时可以复用，不必逐文件重读。

## 基本原则

1. 所有新输入先进入 `raw/`，不得直接写入 `knowledge/`。
2. raw 保存当时收到或记录的内容，不提前改写成可信结论。
3. 修正原始内容应重新采集并生成新的 raw ID，不能静默修改既有 raw。
4. 一个 raw ID 对应一次采集事件；目录导入时每个文件独立分配 ID。
5. 默认禁止导入凭据、私钥、token、`.env`、密码库和浏览器认证数据。

## Origin 词表

`origin` 使用以下值；确有需要时允许扩展，但不能用空泛的 `other`：

| 值 | 含义 |
|---|---|
| `manual` | 本人直接记录或观察 |
| `file` | 本地文件或附件 |
| `web` | 网页或在线文档 |
| `paper` | 论文、标准或研究报告 |
| `book` | 书籍或出版物 |
| `meeting` | 会议、访谈或通话 |
| `conversation` | 聊天、邮件或消息线程 |
| `code` | 源码、配置或构建产物 |
| `dataset` | 数据集或查询结果 |

显式 `raw add --origin` 优先于模板值。通过 stdin 采集只描述传输方式；若已知真实来源，应显式写出 `origin`。

## 来源 Properties

来源存在时优先填写：

- `source_url`：原始 URL，不使用搜索结果或中转页；
- `authors`：作者、发言者或责任人列表；
- `publisher`：发布组织或平台；
- `source_date`：材料首次发布或事件发生日期；
- `retrieved_at`：实际获取日期；
- `license`：许可、保密或使用限制；
- `language`：主要语言；
- `participants`：会议或对话参与者列表。

网页应保存可核验正文或导出文件，不能只保存 URL。二进制文件由 CLI 计算原始字节哈希，sidecar Markdown 只保存规范元数据与定位信息。

## 原始内容要求

- 摘录必须保持原意并标明省略；不能把改写内容伪装成原文。
- 会议和人工记录要区分直接记录、事后回忆和记录者判断。
- 时间使用明确日期或 RFC 3339，不使用“今天”“最近”等相对表达。
- 无法确认作者、日期或出处时留空并在正文标记“待核实”，不得猜测。

raw 是证据而不是最终结论；只有发布到 `knowledge/` 的 Markdown 才能成为最终事实。

raw 正文不进入全文索引，也不能通过 `query` 召回。归档盘点使用 `raw list --unreferenced`，读取材料必须使用明确 raw ID 调用 `raw show`；只有人工确认发布后的 knowledge 才进入检索。
